# 移种只移交元信息，成功后删除本机种子

> **状态**：已实现。

## 背景

torrentfs 把分片取进内存缓存，按需提供给播放器；它从不把内容落盘。用户希望把一个种子交给外部的常驻下载器（先支持 Transmission）继续做种，然后释放 torrentfs 里的这份任务。这条路径有两个容易混淆的理解：复制（本地保留、外部另起一份）与剪切（本地交出后删除）。复制会让两个客户端同时用不同的 peer id 为同一个 infohash 做种，也让同一份内容在 torrentfs 里继续占用缓存与连接配额；用户实际想要的是后者。

另一个事实决定了「交出什么」：缓存里的分片没有任何写回宿主磁盘的代码，`<torrents-dir>` 下只有 metainfo 与内部状态，没有任何内容文件。因此交接的只能是元信息，内容由接收方自己下载或从其他 peer 取得。

## 决定

「移种」= 移交元信息与控制权，成功后删除本机种子（方案 A）：

- 只允许 `ready` 状态（元信息已取得）的种子；交付磁盘上的 `<torrents-dir>/<infohash>.torrent` 的 base64 内容，通过 Transmission 的 `torrent-add` 加入。`adding` 状态的磁力不参与移种。
- 协议固定为 Transmission 的旧 bespoke RPC（kebab-case），因为目标是 3.00：它只支持旧协议，而 4.x 仍兼容旧协议，5.0 才移除。JSON-RPC 2.0（4.1 起）不实现。
- 暂停 = 把该种子的连接配额降到 0，**不发 `stopped` announce**。表层的「先暂停做种」只需要它停止交换数据；移种成功后走删除流程时，那条流程本身会同步上报 `stopped`（见 ADR 0008）。失败复原 = 把配额交还给连接分配器，由它按活动重新计算；不重发 announce，也不重建 torrent 对象。
- 移交与删除在一个异步操作里完成（`202` + operation）：`running` → `completed`（种子已删除）/ `restored`（移交失败，已复原）/ `failed`（移交成功但删除失败，种子停在 `delete_failed`）。
- 移交成功后翻转 sidecar 到 `deleting` 并复用现有删除管线，因此进程在删除阶段崩溃时由 `resumeDeletions` 续跑；移交前的暂停不落盘，进程在移交前崩溃只会留下一个正常做种的种子。
- 不记录「已移种」：种子在成功路径上被删除，没有承载该标记的对象。

## 考虑过的替代方案

- **B：复制（本地保留，外部另起一份）**：被拒。两个客户端用不同 peer id 为同一 infohash 做种，tracker 会把它们当成两个 peer；本地那份还继续占缓存与连接，而用户点「移种」的意图就是收尾。
- **C：把缓存分片写回磁盘再交给下载器**：被拒。项目没有内容落盘路径，做出来等于新写一个下载器；而且内存缓存的容量与 LRU 语义都不适合产出一份完整内容。
- **D：移交磁力 URI，由接收方自己抓元信息**：被拒。`adding` 的种子在 torrentfs 里还没有可校验的元信息，失败语义会分裂成两种；先只做确定的那种。
- **E：暂停时同步上报 `stopped`，复原时重新 announce**：被拒。fork 只有 `AnnounceStopped`，没有强制 re-announce 的 API；复原后要等下一个 announce 周期（3.00 默认 1800 秒）才重新出现在 swarm，等于用一次失败换来半小时的不可见。
- **F：把移种做成同步 `200`，再让前端调一次 `DELETE`**：被拒。删除是异步且有失败态的操作，两次请求之间崩溃会留下「已移交但没删」的种子；一个 operation 才能表达完整结局。
- **G：为移种单独持久化一个状态并续跑**：被拒。暂停到移交是秒级动作，为它加持久状态机的成本高于「重启后照常做种，可能与接收方短暂重复做种」的代价。

## 影响

- 移交依赖外部下载器可达；不可达、认证失败、被拒绝分别有稳定的错误码（`handoff_unreachable` / `handoff_auth_failed` / `handoff_rejected`），operation 进入 `restored`。
- 移交成功后删除失败不回滚：接收方已经在做种，回滚只会制造两份都不完整的状态；种子停在 `delete_failed`，用户可以重试删除。
- Transmission 返回 `torrent-duplicate`（该 infohash 已在其中）视为成功，继续删除本机种子。
- 暂停窗口内读取不隐藏：挂载树与列表照旧，缺片读取会失败，窗口是秒级。
- 配置为 `[handoff.transmission]` 的 `url` / `username` / `password` 三个键，全部热应用；`url` 为空表示未配置，界面把移种入口置为不可用。
- 只覆盖 Transmission 的常规 RPC；qBittorrent 需要在同一层再加一个客户端实现，不影响会话与 API 的形状。
