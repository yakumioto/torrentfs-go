# 运行时设置并入配置 schema，实验常驻并改名 experiments

## 背景

上传限速与上传统计实验是仅有的两组运行时可调设置。上传限速只有 `<torrents-dir>/.metadata/upload_rate.json` 一个持久化位置，没有任何配置键；上传统计实验同时存在 `[lab]` 配置节与 `.metadata/lab_settings.json` 侧车，侧车覆盖配置节。两者都通过独立 API 与页面管理，与 ADR-0001 的"配置 schema 是唯一真相源、配置只从默认值/文件/环境变量三个来源合并"不一致；实验是否启用还取决于启动时的 `[lab]`，后续新增实验无处安放。用户决定把所有设置收敛到一个配置页面共同维护。

## 决定

- 两个侧车退役：上传限速成为顶层 `[upload_rate]` 配置节（`limit` 字节速率；`schedule_start` / `schedule_end` 构成同一自然日窗口，两者同为空表示全天）；实验设置成为 `[experiments.upload]` 配置节。两者自动获得环境变量，并进入 `config print`、启动日志、示例配置与文档生成物。
- **实验常驻**：不再有启用/禁用状态；上传统计实验默认 `mode = "baseline"`，运行中只改模式及其参数（rate / multiplier / jitter / cap），`seed`、`announce_log`、`peer_sample_interval` 仍是重启生效。后续实验各自增加 `[experiments.<name>]` 子节。
- 删除模式推断：`mode` 默认 `baseline`；旧配置只写 `upload_rate` 或 `upload_multiplier` 而不写 mode 的，启动报错并提示补 `mode = "inject"` / `"amplify"`。
- 迁移：启动时若能写配置文件，把侧车值并入配置文件并把侧车归档为 `.migrated`；不能写时以侧车值只读运行并告警"设置尚未迁移"（双轨期，约定后续版本删除）。
- 没有配置文件启动的部署，配置页面只读，上传限速与实验设置也只能在带配置文件启动后管理。
- 命名统一为 experiments：TOML 节、环境变量、API 路径、页面文案与 Go 包名（`internal/lab` → `internal/experiments`）；旧名进入迁移表，启动时报错并给出新名。
- 旧入口下线：上传限速对话框与实验页的设置表单删除；`/experiments` 保留为实验监控页，仪表盘摘要卡与种子详情页对照保留；旧的设置写接口删除，监控数据接口保留并改名。

## 考虑过的替代方案

- 只做 UI 统一、持久化仍分侧车：两个真相源与两套失败语义永久保留。
- 忽略旧侧车：会静默丢掉用户正在依赖的限速与实验设置。
- 启动时强制迁移、失败即退出：只读配置（ConfigMap、`:ro` 挂载）的部署无法升级。
- 无配置文件时自动创建：违反 ADR-0001 明确否掉的隐式搜索路径。
- 保留 `[lab]` 扁平键：后续实验会持续膨胀命名空间，页面的"实验"分类也要跟着堆平铺字段。
- 保留模式推断：实验变多后推断规则难以解释。

## 影响

- 破坏性升级：`[lab]` 键名、`TORRENTFS_LAB_*` 环境变量、`/api/v1/lab` 路径都已进入迁移表并在启动时报错提示新名；删除的旧接口与旧页面入口见 `README.md` 的升级说明。
- `README.md` 里"上传限速在 Web UI 中设置并立即生效，不通过 TOML 或环境变量配置"等表述已改写；示例配置、镜像配置、配置速查与内嵌 schema 文档已随最终 schema 重新生成，并由 CI 逐字节校验。
- 侧车迁移只补配置文件缺失的键（手写值优先），归档为 `.migrated`；不可写部署以侧车值只读运行并告警，下一次成功写回后的启动完成归档。
- 新增配置项进入 schema 后，`config print`、启动日志、文档生成与 CI 逐字节校验自动覆盖。
- 实验常驻意味着 tracker announce 的改写路径始终存在（baseline 只观测、不改写）；不希望承担这层开销的部署没有关闭开关。
