# STRM 直链是带截止时间的凭据

## 背景

签名直链把 URL 本身当作访问凭证：`/stream/<infohash>/<signature>/<path>` 不需要登录态，播放器、代理与日志都能拿到它。原先的签名只覆盖一个常量版本域、infohash 与路径，没有任何时间维度，因此一条链接一旦发出就永久有效，复制到别的部署上也能通过校验。`/stream` 同时没有并发上限，一次批量扫描或一个失控的播放器可以同时打开任意多条读取，把会话级的预取预算吃光。

`.strm` 文本由挂载树虚拟生成（`internal/vfs/strm.go`、`strm_cache.go`），服务器磁盘上不存在陈旧副本；会失效的只有用户导出到别处保存的文件。因此"让旧链接失效"不需要迁移任何持久化数据。

ADR-0003 决定不设会话级**连接**总量上限，那说的是 BitTorrent peer 连接。本决定限制的是 HTTP 请求，两者不是一回事。

## 决定

- 签名载荷升级为 `torrentfs-stream-v2`：域 + 32 字节 infohash + `\x00` + 8 字节大端过期时间 + `\x00` + 路径。过期时间随签名一起进 URL，服务端不需要保存任何已发链接的状态。
- 过期时间按小时向下取整后再加 TTL，因此同一小时内重复生成的链接完全相同。令牌长度固定，`.strm` 的虚拟文件大小本来就不随过期时间变化；取整保证的是**内容**稳定，避免挂载树每小时在同一个文件上报告新的内容。
- 校验先比时间再比 HMAC，允许 60 秒时钟偏移；过期与签名不符对客户端都是 403，不区分细节。
- TTL 是配置项 `http.stream.link_ttl`，默认 `720h`（30 天），重启生效。改 TTL 不会让已发出的链接提前失效，它们仍按自己携带的过期时间走完。
- **硬切**：不保留 v1 签名的兼容窗口。升级后旧的 `.strm` 内容一律 403，重新读取共享或重新导出即可拿到新链接。
- `/stream` 并发上限硬编码为 8，超出返回 503 加 `Retry-After`。它保护的是会话级预取预算，而预算是常量；把上限做成配置项只会制造"调了也没用"的错觉。

## 考虑过的替代方案

- 服务端保存已吊销链接的集合：需要持久化与清理，而链接本身可以自带截止时间。
- 双版本宽限（同时接受 v1 与 v2 签名）：等于没有失效，只是把硬切推迟一个版本。
- 每次生成都写入当前时间：`.strm` 的虚拟大小会随秒变化，挂载树会不断报告文件"变了"。
- 把并发上限做成配置项：与预取预算的常量属性冲突，且没有公认的调优方法。
- 用登录态保护 `/stream`：播放器与外部播放列表拿不到 Cookie，直链的存在意义就是脱离会话。

## 影响

- 升级后所有既有直链立即失效一次；`README` 与 issue 中已写明重新读取或重新导出的做法。
- `.strm` 文本没有长期缓存，读取时重新生成，因此 TTL 改动在下次读取时就体现出来。
- ADR-0003 的 peer 连接决定不受影响；HTTP 并发上限单独存在，且不暴露为配置项。
- 签名测试向量加入过期时间，签名长度由 32 字节变为 40 字节；`/stream` 的 ETag 仍只由 infohash 与路径派生，不随签名轮换。
